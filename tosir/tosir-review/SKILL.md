# Итоговая приёмка задачи

Сначала загрузи tosir и соблюдай его регламент.

## Входные данные

Определи папку задачи, репозитории и подмодули.

Запуск разрешён, если последняя запись — ALL_STAGES_ACCEPTED или USER_DECISION с next=tosir-review. Иначе остановись, ничего не записывая.

Базы сравнения: для каждого репозитория и подмодуля — самая ранняя base по всем IMPL_STARTED.

Перед приёмкой рабочие деревья должны быть чистыми, кроме файлов папки задачи. Иначе остановись, ничего не записывая.

## Проверка

1. Прочитай инструкции проекта, overview.md, task.md (если есть), stage-*.md и log.md.
2. Проверь, что каждый этап имеет REVIEW_ACCEPTED и результаты закоммичены.
3. Изучи изменения от баз до HEAD, кроме файлов папки задачи.
4. Проверь каждый критерий завершения из overview.md, границы и исключения. Убедись, что требования task.md учтены в overview.md и этапах.
5. Выполни проверки из стратегии overview.md с понятными побочными эффектами.

## Ограничения

- Не изменяй код, тесты, конфигурацию, overview.md, task.md и планы. Не выполняй checkout, reset, clean, commit, push или deploy.
- Не запускай действия, меняющие БД или внешние системы, без отдельного разрешения.
- Не создавай планы этапов: пробелы закрывает tosir-plannextstage.
- Разрешено только дополнить log.md.

## Отчёт

1. Репозитории и базы.
2. Каждый критерий завершения: выполнен / не выполнен, с основанием.
3. Замечания по серьёзности: файл и строка, проблема, основание.
4. Проверки и результаты; ограничения.
5. Итог — ровно один, с записью в log.md:
   - TASK_DONE — все критерии выполнены;
   - TASK_GAPS — с перечнем невыполненных критериев в gaps, каждому — новый ID по правилам tosir;
   - REVIEW_BLOCKED — с причиной и требуемым решением пользователя.
