# Итоговая приёмка задачи

## До начала всех работ

Загрузи skill tosir. Используй инструкции из него для понимания общего механизма работ.

## Входные данные

Определи из запроса и контекста папку задачи, репозитории и подмодули.

Продолжай, только если последняя запись log.md — ALL_STAGES_ACCEPTED или USER_DECISION с next=tosir-review.
Иначе остановись и сообщи текущее состояние, ничего не записывая в log.md.

Базы сравнения: для каждого репозитория и подмодуля — самая ранняя base по всем записям IMPL_STARTED.

## Проверка

1. Прочитай инструкции проекта, overview.md, stage-*.md и log.md.
2. Проверь, что каждый этап имеет REVIEW_ACCEPTED, а результаты закоммичены.
3. Изучи совокупные изменения от баз до HEAD, кроме файлов папки задачи.
4. Проверь каждый критерий завершения из overview.md, границы и исключения задачи.
5. Выполни проверки из общей стратегии overview.md с понятными побочными эффектами.

## Ограничения

- Не изменяй код, тесты, конфигурацию, overview.md и планы.
- Не выполняй checkout, reset, clean, commit, push или deploy.
- Не запускай действия, меняющие БД или внешние системы, без отдельного разрешения.
- Не создавай планы этапов: пробелы закрывает tosir-plannextstage.

Разрешено только добавить запись в log.md.

## Отчёт

1. Проверенные репозитории и базы.
2. Каждый критерий завершения: выполнен / не выполнен, с основанием.
3. Замечания по серьёзности: файл и строка, проблема, основание.
4. Выполненные проверки и результаты, ограничения проверки.
5. Итог — ровно один, с записью в log.md:
   - TASK_DONE — все критерии выполнены;
   - TASK_GAPS — с перечнем невыполненных критериев в gaps;
   - REVIEW_BLOCKED — с причиной и тем, что требуется от пользователя.

После отчёта остановись.
