# Выполнение задачи согласно плану, в несколько этапов

Это регламент, а не автоматический запуск задачи.
За один запуск выполняй только операцию, явно запрошенную пользователем, и остановись после её завершения.
Не выбирай другую модель и не переходи к следующей операции без явного разрешения.

## Файлы папки задачи

- task.md - общее описание задачи, по которому готовится overview.md; файл неизменяемый.
- overview.md - общий план задачи.
- stage-NN.md - план очередного этапа для исполнителя.
- stage-NN-M.md - план доработок этапа.
- log.md - журнал состояния задачи.
- memory.md - короткие заметки агентов по задаче, сделанные по их инициативе: дата/этап + заметка + теги (см. раздел «memory.md»).
- другие файлы, относящиеся к задаче.

Файлы папки задачи не считаются изменениями реализации: они не мешают началу этапа и не проверяются ревью как код.

## Цикл

1. tosir-overview однократно создаёт overview.md и log.md.
2. tosir-plannextstage готовит stage-NN.md.
3. tosir-implementstage выполняет stage-NN.md или stage-NN-M.md.
4. tosir-reviewstage выносит итог:
   - принято (REVIEW_ACCEPTED) — переходим к шагу 2;
   - нужны исправления (REVIEW_REWORK, создан stage-NN-M.md) — переходим к шагу 3;
   - заблокировано (REVIEW_BLOCKED) — ждём решения пользователя.
5. Когда все блоки overview.md приняты, tosir-plannextstage пишет ALL_STAGES_ACCEPTED, а итоговую приёмку выполняет tosir-review.

Принятый этап коммитится до начала следующего.
Коммит выполняет агент ревью этапа при наличии разрешения пользователя, в том числе переданного через workflow.
Без разрешения — сообщает о необходимости коммита и останавливается.

## log.md

Планы описывают задания, но не текущий статус: состояние определяется только по log.md.

Перед работой каждый навык читает log.md и по таблице «Следующий шаг» проверяет, что его запуск разрешён. Если нет, ничего не записывай, а сообщи состояние.

После результата добавь одну строку в конец:

```
<дата время> | <навык> | <модель агента> | <статус> | stage=<stage-NN> | plan=<файл> | <детали ключ=значение>
```

- Существующие строки не меняются. Исправления — только новой записью CORRECTION или USER_DECISION.
- stage — основной этап, plan — файл плана; пустое значение — `-`. Модель, если неизвестна — `unknown`.
- Несколько репозиториев в base перечисляются через запятую: `base=web:a1b2c3d,sub:c3d4e5f`.
- Свободный текст (reason, need, gaps, text) пишется последним полем и не содержит `|`.

| Статус | Кто пишет | Детали |
|---|---|---|
| OVERVIEW_CREATED | overview | — |
| STAGE_PLANNED | plannextstage | closes=ID пробелов (для этапа по TASK_GAPS) |
| IMPL_STARTED | implement | для первого запуска основного этапа — base=HEAD каждого затрагиваемого репозитория и подмодуля, branch |
| IMPL_DONE | implement | changed=файлы, checks=passed/failed/partial |
| IMPL_STOPPED | implement, только после IMPL_STARTED | reason |
| REVIEW_ACCEPTED | reviewstage | — |
| REVIEW_REWORK | reviewstage | next=stage-NN-M.md |
| REVIEW_BLOCKED | reviewstage, review | reason, need |
| ALL_STAGES_ACCEPTED | plannextstage | — |
| TASK_DONE / TASK_GAPS | review | gaps (для TASK_GAPS) |
| USER_DECISION | пользователь или агент по его указанию | next=навык, plan (если нужен), closes (если пробел снимается без этапа), text |
| CORRECTION | пользователь или агент по его указанию | ref=дата исправляемой записи, text |

Пример:

```
2026-11-08 11:00 | tosir-implementstage | anthropic/claude-opus-5-5 | IMPL_STARTED | stage=stage-01 | plan=stage-01.md | base=web:a1b2c3d branch=main
```

Следующий шаг определяется по последней значимой записи — последней строке log.md, не считая записей CORRECTION. Везде в навыках «последняя запись» означает именно её.

CORRECTION не участвует в переходах. Она уточняет детали записи из ref (например, plan, base, changed), и при чтении той записи учитываются её исправления. Статус и следующий шаг CORRECTION не меняет; для этого нужна USER_DECISION.

| Последняя запись | Следующий шаг |
|---|---|
| OVERVIEW_CREATED, REVIEW_ACCEPTED, TASK_GAPS | tosir-plannextstage |
| STAGE_PLANNED, REVIEW_REWORK | tosir-implementstage |
| IMPL_DONE | tosir-reviewstage |
| ALL_STAGES_ACCEPTED | tosir-review |
| IMPL_STARTED, IMPL_STOPPED, REVIEW_BLOCKED | решение пользователя (USER_DECISION) |
| USER_DECISION | навык из её next |
| TASK_DONE | никаких действий, задача завершена |

## memory.md

Файл коротких заметок агентов по ходу задачи: находки о системе и решения, которые полезны другим агентам, но не вошли в overview.md, stage-NN.md или log.md. Заметки пишутся по инициативе агента.

Формат записи — одна строка:

```
[YYYY-MM-DD S{N}] краткий текст заметки #тег #тег
```

- Дата — день, когда сделана заметка; N — номер текущего этапа, `S0` — до первого этапа.
- Текст — одна-две строки, только суть.
- Теги — один или два из списка ниже.

| Тег | Что фиксировать |
|---|---|
| `#arch` | архитектурные находки: структура модулей, потоки данных, неочевидные зависимости |
| `#tech` | технические ограничения и особенности: окружение, инструменты, флаки-тесты, ошибки инструментов |
| `#decision` | принятые решения, не зафиксированные в overview.md или плане этапа |
| `#context` | контекст для будущих этапов: что обнаружено, но сейчас не используется |

Пример:

```
[2026-11-12 S2] auth работает через middleware в src/core/auth.ts, а не в роутах #arch
[2026-11-12 S2] тесты падают при параллельном запуске из-за общего соединения с БД #tech
[2026-11-12 S3] отказались от GraphQL в пользу REST из-за legacy-клиентов #decision
[2026-11-12 S3] модуль notifications косвенно вызывает события через observer #context
```

Правила:

- Пиши только то, что действительно понадобится другому агенту; кратко и без повторов overview.md, планов и log.md.
- Существующие заметки не удаляй и не переписывай; устаревшую заметку дополняй новой.
- Держи файл коротким: ориентир — не более 50 строк. Если он разрастается, не сокращай заметки сам — сообщи пользователю.
- Если файла нет, создай его; в шапке — заголовок `# Memory` и напоминание о формате записи.

## Пробелы итоговой приёмки

- В TASK_GAPS каждый пробел получает ID: `gaps=G1: текст; G2: текст`. Нумерация сквозная для всей задачи, ID не переиспользуются.
- Открытые пробелы — пробелы из последней TASK_GAPS, кроме закрытых.
- Пробел закрыт, если после этой TASK_GAPS есть REVIEW_ACCEPTED этапа, в STAGE_PLANNED которого он указан в `closes=G1,G2`, либо USER_DECISION с `closes=` для этого ID.
- Новая TASK_GAPS заменяет прежний набор: пробелы, которые остались, перечисляются в ней заново под новыми ID.

Изменение overview.md или существующих планов после REVIEW_BLOCKED выполняет пользователь или агент с его явного разрешения; результат фиксируется в USER_DECISION.

Останови и запроси уточнение, если:
- запрошенная операция не соответствует таблице;
- файл из plan (для REVIEW_REWORK — из next) не существует;
- записи нарушают порядок или противоречат друг другу;
- overview.md есть, а log.md нет.
