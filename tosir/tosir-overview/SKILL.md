# Создание общего плана работ

Сначала загрузи tosir и соблюдай его регламент.

## Входные данные

Определи задачу, репозитории и папку задачи из запроса, контекста и task.md, если он существует.
При противоречии источников запроси уточнение; task.md не изменяй.

Убедись что папка задачи ещё не содержит overview.md и log.md, в противном случае остановись и не выполняй никаких действий.
Разработай общий план выполнения задачи, разделенный на отдельные, проверяемые этапы.
Если task.md содержит этапы или их количество, используй их как исходную декомпозицию и проверь по коду, требованиям и зависимостям.
Обязательную декомпозицию соблюдай. Если она невыполнима или противоречит другим требованиям, запроси уточнение.
Предпочтительную декомпозицию можно уточнить; существенные изменения количества, границ или порядка этапов обоснуй в overview.md.
Не выполняй декомпозицию заново без необходимости.
Не прорабатывай каждый этап отдельно, опиши только какую функциональность он должен реализовывать.
Используй минимальное достаточное число этапов. Не выдумывай этапы ради их количества - если задача может быть эффективно решена в один этап - оставь в плане только его. 
Планирование и ревью — операции цикла, а не самостоятельные этапы реализации. Реализацию и необходимые для её приёмки тесты по умолчанию включай в один этап.
Зафиксируй этапы в плане.
Сохрани разработанный план в overview.md.
Создай log.md и запиши в него OVERVIEW_CREATED в формате из tosir.
Создай memory.md по разделу «memory.md» в tosir: заголовок `# Memory`. Если memory.md уже существует, не перезаписывай его.

До составления плана:
- прочитай инструкции проекта;
- исследуй относящийся к задаче код и существующие проверки;
- отдели подтверждённые сведения от предположений.

overview.md должен содержать:
- цель и критерии завершения всей задачи;
- границы и исключения;
- исходное состояние;
- крупные рабочие блоки и зависимости;
- полный перечень основных этапов с номерами stage-NN, названиями, ожидаемыми результатами и зависимостями;
- общее количество основных этапов.
- общую стратегию проверок;
- риски, ограничения и открытые вопросы.

Не составляй подробные задания всех этапов заранее: их уточняет tosir-plannextstage по актуальному коду.

При блокирующей неопределённости запроси уточнение, не сохраняй предположение как согласованное решение.
