# Выполнение этапа

Сначала загрузи tosir и соблюдай его регламент.

## Определение этапа

1. При делегированном запуске с полным пакетом по tosir используй переданные оркестратором план, основной этап, режим и данные Git. log.md не читай: допустимость операции и актуальность плана проверяет оркестратор.
2. При самостоятельном запуске или неполном пакете проверь последнюю значимую запись log.md по таблице tosir. План: STAGE_PLANNED — её plan; REVIEW_REWORK — её next; USER_DECISION с next=tosir-implementstage — её plan. Иначе остановись. Режим и base с branch для доработки или продолжения определи по относящимся к этапу записям с учётом CORRECTION, не загружая всю историю без необходимости.
3. Если переданные сведения противоречат друг другу или прочитанным записям log.md, остановись и сообщи о расхождении.
4. Для stage-NN-M.md выполняй текущее самодостаточное задание. Исходный план и предыдущие доработки по умолчанию не читай. План доработки не разрешает самостоятельно ослаблять исходный контракт этапа.

## Границы чтения

Читай текущий план, инструкции проекта и относящиеся к заданию код и заметки memory.md. log.md читай только в случаях, указанных в разделе «Определение этапа».

Планы других этапов, overview.md и task.md по умолчанию не читай. Для доработки также не загружай исходный stage-NN.md и предыдущие stage-NN-M.md.

Если текущего задания недостаточно для безопасного выполнения, запроси уточнение. Не восстанавливай требования по всей истории задачи и не обходи каталог задачи без необходимости.

## Проверка перед изменениями

1. Если план или границы этапа неоднозначны — запроси уточнение.
2. Прочитай инструкции проекта для затрагиваемых файлов и релевантные заметки memory.md, если он есть. При противоречии с планом запроси уточнение, а не решай сам.
3. Проверь состояние Git. Не перезаписывай пользовательские изменения.
4. Для первого запуска основного этапа затрагиваемые репозитории и подмодули должны быть без незакоммиченных изменений, кроме файлов папки задачи. Иначе остановись.
5. Для доработки или продолжения незакоммиченные изменения этапа допустимы. Используй base и branch из пакета оркестратора либо первой IMPL_STARTED этапа с учётом CORRECTION. Убедись, что base существует в истории, ветка соответствует ожидаемой, а изменения относятся к этапу. При неоднозначности остановись.
6. Для доработки или продолжения: если этап затрагивает репозиторий, для которого нет base, остановись. Для первого запуска основного этапа base фиксируется в пункте 8.
7. Сверь план с фактическим кодом и средствами проверки. При существенном расхождении остановись и предложи варианты.
8. Только после пунктов 1–7 добавь IMPL_STARTED в конец log.md без чтения всей истории: для первого запуска основного этапа — с base=HEAD и branch каждого затрагиваемого репозитория и подмодуля, для доработки или продолжения — без base.

## Реализация

- Выполни только выбранный этап или доработку, без посторонних изменений и рефакторинга.
- Commit, push, deploy и действия на удалённых машинах — только с отдельного разрешения.

## Проверки

- Выполни проверки из текущего плана и просмотри итоговый diff на посторонние изменения.
- Не объявляй этап проверенным, если проверки не выполнены. Ошибки не скрывай и не ослабляй тесты.

## Итог

В ответе: выполненные пункты, изменённые файлы, проверки с результатами, непроведённые проверки с причинами, риски и вопросы.

Если обнаружил архитектурную находку, техническое ограничение или принял решение, которых нет в плане, добавь короткую заметку в memory.md по формату из tosir.

Затем добавь в конец log.md IMPL_DONE (changed, checks) или, если остановился после IMPL_STARTED, IMPL_STOPPED с причиной. Не загружай для этого всю историю и не перезаписывай журнал.
