# Выполнение этапа

## До начала всех работ

Загрузи skill tosir. Используй инструкции из него для понимания общего механизма работ.

## Определение этапа

1. Определи папку задачи и прочитай log.md.
2. План для выполнения:
   - последняя запись STAGE_PLANNED — её plan;
   - последняя запись REVIEW_REWORK — её next;
   - последняя запись USER_DECISION с next=tosir-implementstage — её plan;
   - иначе остановись и сообщи текущее состояние.
3. Если пользователь указал файл плана, не совпадающий с log.md, — остановись и сообщи о расхождении.
4. Для плана доработок stage-NN-M.md прочитай также исходный stage-NN.md и предыдущие доработки.
   Границы и критерии приёмки исходного этапа действуют, если план доработок прямо их не меняет.

## До изменений

1. Если план или границы этапа неоднозначны — запроси уточнение.
2. Прочитай инструкции проекта, применимые к затрагиваемым файлам.
3. Проверь состояние Git. Не перезаписывай пользовательские изменения.
4. Если для основного этапа ещё нет IMPL_STARTED (первый запуск stage-NN.md):
   при незакоммиченных изменениях в затрагиваемых репозиториях или подмодулях
   (кроме файлов папки задачи) остановись и сообщи о них — реализацию не начинай.
   Иначе запиши IMPL_STARTED с base и branch.
5. В остальных случаях (доработка, продолжение после остановки) запиши IMPL_STARTED без base:
   используется base из первой IMPL_STARTED этапа. Незакоммиченные изменения этапа при этом допустимы.
6. Если этап должен изменить репозиторий, для которого нет base, — остановись.
7. Сверь план с фактическим кодом и доступными средствами проверки.

## Реализация

- Выполни только выбранный этап.
- Не расширяй область задачи и не делай посторонний рефакторинг.
- При существенном расхождении плана с кодом остановись:
  опиши расхождение и предложи варианты решения.
- Не выполняй commit, push, deploy и действия на удалённых машинах
  без отдельного разрешения.

## Проверки

- Выполни проверки, предусмотренные планом.
- Просмотри итоговый diff на посторонние изменения.
- Не объявляй этап проверенным, если проверки не выполнены.
- Ошибки проверок не скрывай и не обходи ослаблением тестов.

## Итоговый отчёт

1. Выполненные пункты плана.
2. Изменённые файлы.
3. Команды проверок и их результаты.
4. Невыполненные проверки и причины.
5. Оставшиеся риски и вопросы.

Добавь в log.md запись IMPL_DONE, а при остановке после IMPL_STARTED — IMPL_STOPPED с причиной.

Без отдельного разрешения не выполняй commit, push и deploy.
После отчёта остановись. Следующий этап не начинай.
