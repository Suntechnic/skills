# Выполнение этапа

Сначала загрузи tosir и соблюдай его регламент.

## Определение этапа

1. Прочитай log.md и проверь по таблице tosir, что запуск разрешён.
2. План: последняя запись STAGE_PLANNED — её plan; последняя REVIEW_REWORK — её next; последняя USER_DECISION с next=tosir-implementstage — её plan. Иначе остановись.
3. Если пользователь указал файл плана, не совпадающий с log.md, — остановись и сообщи о расхождении.
4. Для stage-NN-M.md прочитай также stage-NN.md и предыдущие доработки. Критерии приёмки исходного этапа действуют, пока план доработок их прямо не меняет.

## Проверка перед изменениями

1. Если план или границы этапа неоднозначны — запроси уточнение.
2. Прочитай инструкции проекта для затрагиваемых файлов и memory.md, если он есть. Учти заметки, относящиеся к этапу; при противоречии с планом запроси уточнение, а не решай сам.
3. Проверь состояние Git. Не перезаписывай пользовательские изменения.
4. Для основного этапа (нет IMPL_STARTED): затрагиваемые репозитории и подмодули должны быть без незакоммиченных изменений, кроме файлов папки задачи. Иначе остановись.
5. Для доработки или продолжения после остановки незакоммиченные изменения этапа допустимы; base берётся из первой IMPL_STARTED этапа.
6. Если этап затрагивает репозиторий без base, остановись.
7. Сверь план с фактическим кодом и средствами проверки. При существенном расхождении остановись и предложи варианты.
8. Только после пунктов 1–7 запиши IMPL_STARTED: для основного этапа — с base и branch, для доработки или продолжения — без base.

## Реализация

- Выполни только выбранный этап, без посторонних изменений и рефакторинга.
- Commit, push, deploy и действия на удалённых машинах — только с отдельного разрешения.

## Проверки

- Выполни проверки из плана и просмотри итоговый diff на посторонние изменения.
- Не объявляй этап проверенным, если проверки не выполнены. Ошибки не скрывай и не ослабляй тесты.

## Итог

В ответе: выполненные пункты, изменённые файлы, проверки с результатами, непроведённые проверки с причинами, риски и вопросы.

Если обнаружил архитектурную находку, техническое ограничение или принял решение, которых нет в плане, добавь короткую заметку в memory.md по формату из tosir.

Затем запиши в log.md IMPL_DONE (changed, checks) или, если остановился после IMPL_STARTED, IMPL_STOPPED с причиной.
